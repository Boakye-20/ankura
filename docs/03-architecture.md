# 03 · Architecture

## Overview
```
Browser (Next.js pages)                      Server (Next.js route handlers)              Anthropic API
───────────────────────                      ────────────────────────────────             ─────────────
Work queue / case view  ── GET /api/cases ──▶ loads data/complaints.json + demo outputs
"Run AI on this case"   ── POST /api/run ───▶ 1 mask ─▶ 2 triage ───────────────────────▶ triage model
                                              3 retrieve (BM25, local)
                                              4 draft ─────────────────────────────────▶ draft model
                                              5 verify (code only)
                                              6 route (code only)
                        ◀── result + audit events (masked text only; token map stays server-side)
Decision panel          ── localStorage (session actions + audit events)
Model assurance         ── GET /api/eval ───▶ data/eval-results.json
```
Modes:
- **Demo mode** (no `ANTHROPIC_API_KEY`): `/api/run` returns the stored result for that case from `data/demo-outputs.json`. "Try your own complaint" is disabled with an explanation.
- **Live mode** (key present): `/api/run` executes the pipeline. Add a simple rate limit (for example 20 runs per IP per hour, in memory) and a maximum input length of 3,000 characters.
- Expose the mode via `GET /api/status` → `{ mode: "demo" | "live", models: {...}, policyVersion, promptVersion }`, shown in the footer.

## Data model (`lib/types.ts`)
```ts
type Clause = { id: string; doc: string; section: string; text: string };   // id e.g. "POL-04 §2.1"

type Complaint = {
  ref: string;                 // "CMP-2026-104712"
  received: string;            // ISO date
  channel: "Phone" | "Email" | "Web form" | "App chat" | "Branch" | "Letter";
  product: string;
  customer: { name: string; account?: string; sortCode?: string; email?: string; phone?: string; postcode?: string }; // synthetic, never sent to the model
  text: string;                // raw complaint text (contains synthetic personal data)
  caseNotes: { id: string; date: string; author: string; text: string }[];
  labels: GoldLabels;          // human labels for evaluation, never shown to the model
};

type GoldLabels = {
  category: Category;
  vulnerable: boolean;
  paymentServices: boolean;            // decides 15 business days vs 8 weeks
  summaryResolutionEligible: boolean;
  route: "Handler" | "Senior" | "Fraud & Disputes" | "Lending Support" | "Vulnerability Team" | "Complaints Management";
  expectedClauses: string[];           // clause IDs a good answer should rely on
  adversarial?: "injection" | "fabricated_policy" | "obfuscated_pii" | "redress_bait" | "hidden_vulnerability" | "off_topic";
  maxRedress?: number;                 // the correct maximum in £, if any
};

type Category = "Unauthorised payment" | "APP scam" | "Charges and interest" | "Service and conduct"
  | "Card delivery and access" | "Account administration" | "Lending and affordability" | "Bereavement";

type TriageOutput = {
  category: Category; categoryConfidence: number;   // 0..1
  vulnerable: boolean; vulnerabilityIndicators: string[];
  paymentServices: boolean; summaryResolutionEligible: boolean;
  injectionSuspected: boolean; summary: string; keyFacts: string[];
};

type DraftOutput = {
  response: { text: string; citations: string[] }[];   // one entry per sentence or short paragraph
  proposedRedress: { amount: number; basis: string; clause: string } | null;
  handover?: HandoverPack;
};

type HandoverPack = {
  team: string; issue: string;
  actionsTaken: { text: string; source: string }[];     // source = case note ID or clause ID
  decisionsRequired: { question: string; clause: string }[];
  missingInformation: string[];
};

type Check = { id: string; label: string; result: "Pass" | "Fail" | "Refer"; detail: string };

type PipelineResult = {
  ref: string; mode: "demo" | "live"; maskedText: string; tokenCount: number;
  triage: TriageOutput; retrieved: (Clause & { score: number })[];
  draft: DraftOutput | null; checks: Check[];
  route: GoldLabels["route"]; requiresSeniorCoApproval: boolean; deadline: { basis: string; total: number; used: number; unit: string };
  audit: AuditEvent[]; usage: { inputTokens: number; outputTokens: number; costGbp: number; ms: number };
  promptVersion: string; policyVersion: string; model: { triage: string; draft: string };
};

type AuditEvent = { ts: string; ref: string; actor: string; event: string; detail: string };
```

## Audit events (minimum set)
| Actor | Event | Detail |
|---|---|---|
| System · masking | Personal data masked | n tokens, types masked |
| System · triage | Classified | category, confidence, flags, model, prompt version |
| System · retrieval | Policy retrieved | clause IDs and scores |
| System · drafting | Draft generated / Draft withheld | clause IDs cited, or reason withheld |
| System · verification | Check failed | check ID and reason (one event per failure) |
| System · routing | Routed | route and reason |
| Staff | Personal data revealed | who, when |
| Staff | Approved / Amended / Escalated / Co-approved / Returned | reason code + comment |

## Security and privacy notes (put a short version in the README)
- The token map (token → real value) never leaves the server function and is never logged.
- Only masked text, retrieved clauses and structured triage go to the model.
- No customer data is stored server-side. The synthetic dataset is public by design.
- The API key is server-side only; client bundles must not reference it (check with `grep` after build).
